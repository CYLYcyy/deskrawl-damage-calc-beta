# 全局最优配装/天赋求解器方案

> 来源：`OPT_ALGORITHM.md`（全篇经复审确认论证与行号引用准确）、`opt-prototype.mjs`（可运行原型）、`FRONTEND_PLAN.md` §功能 C。
> 目标函数 `simulate()` 一律视为**黑盒 oracle**：只调用 `score(x) -> number`，不假设连续/可导/凸/单调，也不评判游戏机制正确性。
> 适用对象：天赋点法（70 点 / 单职业 ~9 行 / ~45 变量）与装备主词条分配（离散预算 / 上限 / 部位限制）——**同一个数学模型**。

## 1. 结论摘要

| 项目 | 结论 |
|---|---|
| 精确全局最优 | **在黑盒 + 非凸 + ~45 变量 / 70 点规模下不可行**。认证最优最坏需查询近乎全部可行点（~10²⁵ 量级），分钟级预算无解。这是信息论下界，不是实现问题。 |
| 推荐算法 | **分层混合求解器**：① 专精互斥组精确枚举 → ② 单变量全范围坐标扫描 → ③ 块重置 / 2-opt → ④ 多起点 + 扰动重启 → 全程记忆化缓存；可选 ⑤ 多保真度代理筛选。 |
| 最优性保证 | **结构约束精确**（预算/上限/门槛/互斥）、**阈值变量全范围精确枚举**；整体为**高质量近似**，**不提供最坏情况精确保证**。 |
| 调用量 | 约 **3 万～8 万次唯一调用**（缓存去重后）；代理筛选再降 3–5 倍。 |
| 运行时间 | 默认 15–40 分钟；低保真粗筛 5–10 分钟；并行 Worker 1–3 分钟。 |
| 现状 `autoTalents` | 逐点贪心 + 900 次单点交换（`engine.js:939-993`），原型中**损失 44%**——只能当基线/种子，不能叫"最优"。 |

## 2. 统一形式化

```
maximize   f(x)                         # f = simulate(...).dps，黑盒
subject to x_i ∈ {0,1,...,u_i}           # 每个天赋/词条上限
           Σ x_i ≤ B                     # 预算（天赋 70；词条由装分/稀有度决定）
           互斥组 G：Σ_{i∈G} x_i ≤ 1      # 专精行三选一
           行门槛 at_r：若行 r 有投入，则其它行已投点数 ≥ at_r
           部位/职业/元素限制：x_i 仅在对应槽位下可投
```

**为什么难**：`f` 含乘区相乘（边际递减 → 非可加）与暴击/档位阈值（跳变 → 非凸、局部非单调）。逐点贪心只看"加 1 点"的即时边际，在阈值前收益极低时永远跨不过山谷；单点交换一次只挪 1 点，同样跨不过需连续挪多点的阈值。

## 3. 精确最优不可行的论证

1. **组合爆炸**：45 变量、上限均值约 7、预算 70 → 可行解 ~10²⁵～10³⁰ 量级。
2. **黑盒无法构造非平凡上界**：Lipschitz 界因阈值跳变失效且 L 未知；区间算术经 640～800 步时间循环与大量 `if` 后膨胀为 `(-∞,+∞)`；阈值破坏单调性 → 次模贪心无保证。
3. **信息论下界**：无结构黑盒要*证明*全局最优，最坏必须查询所有可行点（no-free-lunch）。10²⁵ 点 × 30ms ≈ 10²² 秒。
4. 结论：分钟级预算下只能二选一——**(a)** 放弃最坏情况保证、追求实践命中全局最优（本方案）；**(b)** 对 `f` 附加结构假设换条件保证。

## 4. 推荐算法（分层混合）

```
solve(score, meta, B):
  1. 识别互斥组 G（专精行 [10,30,60]）：每组 3~4 选项 → 组合 ≤ 64
  2. 对每个专精组合 g:
       a. 种子 = 均匀分配 + R 个随机分配（修复为可行）
       b. 每种子循环至收敛:
            i.   坐标全范围扫描：每个非专精变量 v 枚举 k=0..u_v，用真实 score 取最优
            ii.  块重置 / 2-opt：从 v 挪 1~3 点到 w，处理协同
       c. 记录该组合最优
  3. 取所有组合中最优，用真实 score 复核
```

- **专精组合精确枚举**：黑盒问题里唯一能"免费"拿到的精确性（≤64 组合）。
- **坐标全范围扫描**：把决策粒度从"加 1 点"改成"把变量整体设为 0..max 任意值"，**一步跨过阈值山谷**——这是贪心做不到的。
- **2-opt**：阈值常与专精协同（如 D1 降低暴击阈值），需两变量同时变化。
- **记忆化**：`score(x)` 按分配序列化 key 缓存；原型去重比约 1:10。
- **多保真度**：粗筛用 `duration=8~12`，top 候选切回 `duration=32` 精评（阈值类机制短 duration 可能失真，精评不可省）。
- **代理筛选**：坐标扫描用 3~5 点拟合二次代理预测最优 k，只对 2~3 候选查真实 score；最终精修关掉。

## 5. 近似性声明（必须如实对用户讲）

| 层次 | 是否提供 | 说明 |
|---|---|---|
| 严格最坏情况精确最优 | ✗ | 黑盒非凸下不可实现；任何声称精确的方案要么偷假设，要么在解代理模型。 |
| 结构约束精确 | ✓ | 所有被评估分配满足预算/上限/门槛/互斥；专精组合完全枚举。 |
| 单变量阈值精确 | ✓ | 坐标全范围扫描穷尽单变量所有取值。 |
| 小规模穷举校验 | ✓ | 原型 16 点玩具问题已穷举确认命中全局最优。 |
| 条件保证（假设次模） | 可选 | 固定阈值档位后贪心有 `(1−1/e)` 近似（matroid 下 1/2）——**依赖假设，不能对真实 f 宣称**。 |
| 概率保证（贝叶斯代理） | 可选 | GP 拟合 + UCB 分支定界给出概率间隙，非最坏情况。 |
| 经验最优性 | ✓ | 多起点反复收敛同一分配、扩大重启不再改善。 |

**给用户的准确表述**：本算法是"**带结构精确性的高质量启发式**"，不是"可证明的全局最优求解器"。结果卡须附收敛证据（N 个起点中 M 个命中同一解）与近似性说明；若需可审计证书，唯一严格路径是让用户/机制侧提供 `f` 的可分解解析结构。

## 6. 接入方式（唯一耦合点是 score）

```js
const score = (talents) => Engine.simulate({ ...cfg, talents }, { duration: 32, lite: true }).dps;
const rows = CLASSES[cfg.classKey].talents;
const meta = { budget: 70,
  vars: rows.flatMap((row, ri) => row.items.map(t => ({ id: t.id, max: t.max, row: ri,
    mutexGroup: [10,30,60].includes(row.at) ? `spec_${ri}` : null }))),
  rowThreshold: rows.map(r => r.at) };
const best = solve(score, meta, { restarts: 8 });  // best.allocation 回填 cfg.talents
```

词条问题同理：预算由装分/稀有度算得，vars 由 `AffixMath` 的词条池按部位/职业/元素过滤生成。`score` 输入必须是**完整分配对象**，确保相同分配映射到相同缓存 key。

## 8. 风险与边界

- 阈值过多且相互独立时坐标扫描仍可能卡住 → 增重启数、模拟退火式扰动或贝叶斯代理。
- `simulate` 当前确定性、无噪声；若未来引入随机性需多次采样并保证缓存键含随机种子。
- 门槛语义若从"全局累计点数"改为"行内前置点数"，只改元数据/可行性检查，算法主体不变。
- 默认预算用满；若出现"少投更好"，坐标扫描覆盖 k=0 且预算为 ≤B，不会漏解。
- **不同口径（单跳/周期、静电相乘/加算、不同未决项裁决）是不同求解任务，结果不可混比**——口径选择必须纳入输入快照与缓存键。
