# 技能等级倍率与符文数据

> 来源：`SKILL_RUNE_RESEARCH.md` §1–4（A 级：游戏 SO 直出 + 指令级逆向），`runes.js`（199 符文已落地），`data.js`（技能 `pct` 为 10 级值、`perLevel` 为每级增量）。
> 证据等级：**A**=官方/游戏本体逆向；**B**=社区数据库；**C**=跨源推断；**D**=查不到。
> **已剔除的证伪值**：闪电风暴 **218%** 是第三方 skill 仓库的二手记录（B 级），按用户拍板弃用；本库取 **225%**（SO 逆向 A 级）。"20 级是有效上限"是数据站 UI 滑块上限，不是游戏硬上限；按用户拍板，技能等级可经符文推到 **50+**。

## 1. 技能等级 → 倍率公式（A）

```
倍率(N) = Base + N × PerLevel        （N 为技能等级，1–10 逐级验证，线性无递减）
1 级 = Base + PerLevel                （网页把 Base 标成 level 1 存在 1 级偏移，以本式为准）
10 级 = Base + 10 × PerLevel          = 本地 data.js 的 ab.pct（10 级基准）
N > 10：倍率(N) = pct + (N - 10) × perLevel    （引擎 pctAtLevel 的实现，可外推到 50+）
```

- `MaxAbilityLevel = 10` 只是**靠使用升级**的上限；官方原文 "each levels to 10 through use and further through runes"（B），符文可超上限（用户拍板：可推 50+）。
- 技能升级经验：`AbilityBaseXPToLevel=135`、`AbilityXPGrowthPerLevel=1.5`（A）。
- 符文槽在英雄 40/45/50/55/60/65 级各开 1 槽（A）。
- 11 级以上倍率游戏内直接实测表**查不到（D）**；引擎按同一斜率外推，若用户有面板截图请录入覆盖（见 `measurement-guide.md`）。

## 2. 符文总数与构成（A）

**当前 1.1.11a 共 199 条**：9 Uncommon 蓝 + 56 Rare 金 + 56 Grand 大金 + 78 套装件。
演变链：**119（发售）→ 151（1.0.1，+32 Grand）→ 199（1.0.2，+48 符文）**，官方补丁原文与 SO `RuneData.json` 计数闭合。TechWiser / PGG 的"119"与多个 SEO 站的"151"都是过期快照。每职业当前 14 对 Rare/Grand。

符文机制（A）：符文等级上限 6，1→6 共 5 次成长；单件属性 `base` 为 1 级值，**N 级 = base + (N−1)×per**；蓝/金/大金可重复装备，套装 6 件不可重复；套装触发 2/4/6 件，6 件需 65 级开满槽。

## 3. 技能等级授予公式（A，指令级逆向）

```
授予等级 = Levels + floor(runeLevel / EveryNRuneLevels)
Rare: Levels=2, Grand: Levels=4, EveryN=3
→ 符文 1–2 级 +2/+4；3–5 级 +3/+5；6 级 +4/+6
```

实现：`RuneData.grantedLevels(runeLevel, baseLevels)`；`RuneData.applyRunes(cfg, s)` 把授予写入 `cfg.skillLevels[技能id]`（引擎 `pctAtLevel` 据此缩放），**不写 `s.ability[id]`**（那是"技能专属 +%伤害"乘区，写串会算错）。符文 2–5 级游戏内数值未实测（B 站明确标注待确认），按 SO 线性公式外推属 C 级。
